## Контекст

Команда из четырёх человек разрабатывает PCPulse.

До перехода зависимости фиксировались в requirements.txt. Существовавший pyproject.toml содержал некорректное имя проекта и пустой список зависимостей.

Практика №3 требует pyproject.toml и lock-файл. Окружение должно воспроизводиться на компьютерах участников и при сборке Docker-образа.

Версия Python для окружения практики — 3.13.

## Рассмотренные варианты

| Критерий | pip + requirements.txt | Poetry | uv |
|---|---|---|---|
| Файлы зависимостей | В исходном варианте requirements.txt | pyproject.toml и poetry.lock | pyproject.toml и uv.lock |
| Прямые и транзитивные зависимости | В исходном pip freeze смешаны | Прямые в pyproject, дерево в lock | Прямые в pyproject, дерево в lock |
| Версия Python | Задаётся отдельно | Ограничение Python и выбор окружения | requires-python и .python-version |
| Dev-зависимости | Отдельные списки по соглашению | Группы зависимостей | Группы зависимостей |
| Проверка согласованности lock | В исходном варианте отсутствует | poetry check --lock | uv sync --locked |
| Установка в образ | pip install -r requirements.txt | Экспорт из poetry.lock | uv sync --locked --no-dev --no-install-project |

### Вариант A: pip и requirements.txt

Преимущества:

- Уже использовался в проекте.
- Не требует дополнительного менеджера.

Недостатки:

- Исходный файл смешивал прямые и транзитивные зависимости.
- Исходный вариант не выполняет требование практики о pyproject.toml и lock-файле.

Вариант отклонён.

### Вариант B: Poetry

Преимущества:

- Создаёт pyproject.toml и poetry.lock.
- Поддерживает группы зависимостей.

Недостатки:

- Для предложенного в практике Dockerfile нужен плагин экспорта.
- Экспортированный requirements.txt необходимо обновлять вместе с poetry.lock.

Вариант не выбран.

### Вариант C: uv

Преимущества:

- Создаёт pyproject.toml и uv.lock.
- Использует lock-файл непосредственно при сборке образа.
- Поддерживает фиксацию Python через .python-version.

Недостатки:

- Требует установки инструмента у участников.
- Версию uv в образе необходимо согласовать с версией, создавшей lock-файл.

Вариант выбран.

## Решение

Используем uv.

### Как ставятся зависимости

Для разработчика:

```powershell
uv sync --locked
```

Запуск приложения:

```powershell
uv run uvicorn main:app --reload
```

Установка в Dockerfile, проверенная сборкой на практике №3:

```dockerfile
COPY --from=ghcr.io/astral-sh/uv:0.13.9 /uv /bin/uv
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev --no-install-project
```

### Правила управления зависимостями

1. В Git сохраняются pyproject.toml, uv.lock и .python-version.
2. Основная зависимость добавляется командой `uv add имя-пакета`.
3. Dev-зависимость добавляется командой `uv add --dev имя-пакета`.
4. Обновлённые pyproject.toml и uv.lock включаются в один PR.
5. Перед merge выполняется `uv sync --locked`.
6. Папки venv и .venv не добавляются в Git.
7. Старый requirements.txt удалён.

## Обоснование решения

uv выполняет требования практики о pyproject.toml и lock-файле.

Использование uv.lock непосредственно в Docker позволяет не поддерживать дополнительный экспортированный список зависимостей.

Файл .python-version фиксирует Python 3.13 для локальной работы. Dockerfile использует python:3.13-slim.

## Последствия

### Положительные

- Прямые зависимости отделены от полного дерева версий.
- Локальная установка и сборка используют один lock-файл.
- Версия Python фиксируется явно.
- После изменения main.py шаг установки зависимостей взят из кэша: CACHED.
- Первая сборка заняла 8.90 с. Повторная сборка после изменения main.py заняла 1.69 с.

### Отрицательные

- Каждому участнику требуется установить uv.
- Старые инструкции запуска через requirements.txt заменены.
- Необходимо согласовывать версию uv в окружении разработчика и Dockerfile.

## Риски и митигация

| Риск | Митигация |
|---|---|
| uv.lock не соответствует pyproject.toml | Выполнять uv sync --locked |
| Локальная версия Python отличается от контейнера | Использовать .python-version с 3.13 и python:3.13-slim |
| Версия uv в контейнере отличается от использованной для lock | Фиксировать соответствующую версию в теге образа uv |
| Команда установки в Dockerfile не сработает | На практике №3 команда проверена успешной сборкой образа |
